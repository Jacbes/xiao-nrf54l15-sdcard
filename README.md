# XIAO nRF54L15 — тест и запись SD-карты по SPI

Прошивка для платы **Seeed Studio XIAO nRF54L15 (Sense)**, которая инициализирует
microSD-карту по SPI, проверяет её полноценным самотестом (чтение/запись/сверка) и
на каждой загрузке создаёт на карте новый файл `test{N}.txt` с текстом `Hello`.

В репозитории **две готовые версии**:

| | `sdcard_softspi` | `sdcard_hwspi` |
|---|---|---|
| Тип SPI | программный (bit-bang, GPIO) | **аппаратный** (SPIM22) |
| Пины SCK / MOSI / MISO | P2.01 / P2.02 / P2.04 (D8 / D10 / D9) | **P1.05 / P1.06 / P1.07 (D1 / D2 / D3)** |
| Пин CS | P1.04 (D0) | P1.04 (D0) |
| Скорость записи | ~84 КиБ/с | **~441 КиБ/с** (×5) |
| Скорость чтения | ~68 КиБ/с | **~581 КиБ/с** (×8.5) |
| USB-консоль (COM-порт) | сохранена | сохранена |
| Стабильность при «тёплом» сбросе | средняя (нужен цикл опроса) | высокая |

Обе версии собраны, прошиты и проверены на реальном железе (16 ГБ карта, FAT32):
**самотест проходит 22/22, файлы `test{N}.txt` создаются и накапливаются**.

## Оборудование

- **Плата:** Seeed Studio XIAO nRF54L15 (Sense).
- **SoC:** Nordic nRF54L15 — Arm Cortex-M33 @128 МГц, 1.5 МБ NVM (RRAM), 256 КБ RAM,
  многопротокольное радио 2.4 ГГц.
- **Программатор:** встроенный **CMSIS-DAP** (USB VID `2886` / PID `0066`) — внешний
  отладчик (J-Link и т.п.) **не нужен**, прошивка заливается прямо по USB.
- **Консоль:** встроенный USB-Serial мост выводится в систему как **COM-порт**
  (в нашем случае `COM10`), скорость **115200 8N1**. Подключён к UART20 nRF54L15
  (пины P1.09 TX / P1.08 RX).
- **Карта:** microSD, отформатированная в **FAT32**.

### Версия `sdcard_hwspi` (аппаратный SPI, рекомендуется)

| SCK       | **D1**   | P1.05    |
| MOSI      | **D2**   | P1.06    |
| MISO      | **D3**   | P1.07    |
| CS        | **D0**   | P1.04    |
| VCC       | 3V3      | —        |
| GND       | GND      | —        |

### Версия `sdcard_softspi` (программный SPI)

| Сигнал SD | XIAO пин | nRF54L15 |
|-----------|----------|----------|
| SCK       | **D8**   | P2.01    |
| MOSI      | **D10**  | P2.02    |
| MISO      | **D9**   | P2.04    |
| CS        | **D0**   | P1.04    |

| GND       | GND      | —        |

> для некоторых карт это повышает надёжность инициализации. Обязательным не является.

## Как это устроено (инженерные решения)

У nRF54L15 «последовательные» блоки нумеруются **00, 20, 21, 22, 30**. Каждый блок —
это **один** аппаратный узел, который можно использовать *либо* как SPI, *либо* как
UART, *либо* как I2C (одновременно нельзя). Отсюда все нюансы.

**Почему в программной версии — bit-bang, а не аппаратный SPI на пинах P2:**

- Пины D8/D10/D9 = **P2.01/02/04**. «Родной» для порта P2 аппаратный SPI — это
  **SPIM00**, но у него **минимальная тактовая частота 2 МГц**, а SD-карте для
  инициализации нужен клок **≤400 кГц**. → SPIM00 не может поднять карту.
- Второй вариант для P2 — **SPIM20**, но это тот же блок, что и **UART20 =
  USB-консоль (COM-порт)**. Заняв его под SPI, мы теряем консоль.
- Программный SPI (`zephyr,spi-bitbang`) дёргает обычные GPIO, поэтому спокойно
  работает на 400 кГц, не занимает ни один «serial»-блок и **сохраняет консоль**.

**Почему в аппаратной версии SPI перенесён на пины P1 и используется SPIM22:**

- На nRF54L15 аппаратный SPI-**мастер** из PERI-домена (SPIM20/21/22) **не умеет
  выводиться на пины P2** — из PERI-домена порт P2 доступен только для SPIS/UARTE,
  но не для SPIM. Это проверено вживую: SPIM21 на P2.01/02/04 не инициализирует
  карту даже на свежепере-питанной карте и с включённым constant-latency.
- Зато SPIM20/21/22 **штатно работают мастерами на порту P1**. Поэтому сигналы
  перенесены на **P1.05/06/07** и подключены к **SPIM22**. SPIM22 делит блок только
  с I2C22 (внешний I2C, здесь не используется; встроенный IMU сидит на I2C30), так
  что консоль на UART20 → **COM-порт остаётся рабочим**, и светодиод для логов
  **не нужен**.

Итог: аппаратный SPI даёт ×5–8 по скорости и надёжнее поднимается после сброса.

## Что делает прошивка

Одинаково в обеих версиях, на **каждой загрузке**:

1. **Ждёт карту** — опрашивает инициализацию SD каждые 2 с, пока карта не ответит.
   Это позволяет чинить проводку / переустанавливать / пере-питывать карту «вживую»
   без перепрошивки, и сглаживает случайные срывы инициализации.
2. **Создаёт `test{N}.txt` = `Hello`** — берёт наименьший свободный номер `N`, поэтому
   каждая загрузка оставляет новый файл: `test1.txt`, `test2.txt`, `test3.txt`, …
   (файлы **накапливаются**, не перезаписываются).
3. **Идентификация карты** — число секторов, размер сектора, ёмкость.
4. **Монтирование FAT**, объём тома, листинг корня.
5. **Малый файл** — запись → чтение → побайтовая сверка.
6. **Большой файл (128 КиБ)** — запись и чтение с замером скорости, проверка
   целостности (без повреждений).
7. **Удаление** временных файлов, размонтирование/повторное монтирование.
8. **Heartbeat** — раз в 3 с печатает текущий статус (какой `test{N}.txt` записан, либо
   что карта недоступна), чтобы состояние было видно при открытии консоли в любой
   момент. Дополнительных файлов при этом не создаёт.

В конце печатается итог: `RESULT: N checks passed, M failed` и вердикт
`SD CARD TEST: PASSED / FAILED`.

## Требования и установка тулчейна

- **nRF Connect SDK v3.4.0** (Zephyr 4.4.0) с тулчейном. Ставится через `nrfutil`:

```
nrfutil install sdk-manager
nrfutil sdk-manager config install-dir set C:\ncs
nrfutil sdk-manager install v3.4.0
```

- **Python 3.12** + пакеты для прошивки и логов:

```
python -m pip install pyocd pyserial
```

`pyocd` умеет работать со встроенным CMSIS-DAP платы и имеет встроенный таргет
`nrf54l` (для nRF54L15) — отдельный отладчик не требуется.

> Замечание: собирайте проект в пути **без пробелов и кириллицы** (например,
> `C:\work\...`). Пути вида `C:\Users\...\Бобров Работа\...` ломают сборку Zephyr/CMake.

## Сборка

Из корня нужного проекта (пример для аппаратной версии; путь до SDK — `C:\ncs\v3.4.0`):

```
nrfutil sdk-manager toolchain launch --ncs-version v3.4.0 --chdir C:\ncs\v3.4.0 -- ^
  west build -b xiao_nrf54l15/nrf54l15/cpuapp C:\work\xiao-nrf54l15-sdcard\sdcard_hwspi ^
  -d C:\work\xiao-nrf54l15-sdcard\sdcard_hwspi\build -p always
```

Для программной версии подставьте `sdcard_softspi`. Готовый бинарник появится в
`<project>/build/<project>/zephyr/zephyr.hex`.

## Прошивка

Через встроенный CMSIS-DAP (внешний отладчик не нужен):

```
python -m pyocd flash -t nrf54l C:\work\xiao-nrf54l15-sdcard\sdcard_hwspi\build\sdcard_hwspi\zephyr\zephyr.hex
```

Либо сразу готовым бинарником из репозитория:

```
python -m pyocd flash -t nrf54l prebuilt\sdcard_hwspi.hex
```

Предупреждение `NRF54L15 is not in a secure state` — информационное (плата в открытом
lifecycle-состоянии), это нормально.

## Просмотр логов

Консоль — на **COM-порту** платы, 115200 8N1. Скрипт `tools/read_serial.py` сбрасывает
плату через CMSIS-DAP и захватывает вывод, распознавая итог PASS/FAIL:

```
python tools\read_serial.py COM10 40
```

(`COM10` — подставьте свой порт; `40` — сколько секунд слушать.) Можно смотреть и любым
терминалом (PuTTY, `screen`, монитор порта в VS Code) на 115200.

## Настройка

- **Частота SPI.** В `boards/...overlay`, узел `sdhc@0`, свойство
  `spi-max-frequency = <8000000>` (8 МГц). SPIM22 тянет до **24 МГц** — можно поднять
  `spi-max-frequency = <24000000>` для ещё большей скорости (зависит от карты и
  качества монтажа).
- **Только создание `test{N}.txt` без полного теста.** В `src/main.c`, в `main()`,
  уберите вызовы `test_small_file()`, `test_large_file()`, `test_cleanup_and_remount()`
  — останется ожидание карты + `create_boot_file()`.
- **Содержимое файла.** В `create_boot_file()` строка `fs_write(&f, "Hello", 5)`.
- **Другие пины.** Правьте `psels` в `boards/...overlay` (формат
  `NRF_PSEL(SPIM_SCK, порт, пин)`). Помните про ограничение: аппаратный SPIM-мастер
  на nRF54L15 работает на **P1**, а не на P2.

## Диагностика

- **`Card error on CMD0` / карта не поднимается.**
  - Проверьте контакты SCK/MOSI/MISO/CS и питание 3V3/GND.
  - Убедитесь, что карта в **FAT32**.
  - SD-карта **не пере-питывается** при сбросе МК: если карта «залипла» после сброса,
    поможет отключить/подключить её питание (или USB платы). Прошивка сама повторяет
    инициализацию в цикле, так что после восстановления контакта/питания карта
    подхватится без перепрошивки.
- **В консоли пусто.** Порт/скорость: 115200 8N1; правильный COM-порт; при открытии
  порта не должно дёргаться DTR/RTS (скрипт это учитывает).
- **Сборка падает на путях.** Собирайте в пути без пробелов и кириллицы.

## Справочник: SPI-инстансы nRF54L15

| Инстанс | Делит блок с | Порт-«родной» | Конфликт с USB-консолью | Годен для SD |
|---------|--------------|---------------|--------------------------|--------------|
| SPIM00  | UART00       | P2 (спец.)    | нет                      | ❌ мин. 2 МГц |
| SPIM20  | **UART20 = консоль** | P1 (+P2) | **да**                | по частоте — да |
| SPIM21  | UART21 (D6/D7) | P1          | нет                      | да (только P1) |
| SPIM22  | I2C22        | P1            | нет                      | ✅ да (P1) |
| SPIM30  | I2C30 = IMU  | P0            | нет                      | ❌ P0, конфликт с IMU |

Вывод: чтобы аппаратный SPI не конфликтовал с USB-консолью, используйте **SPIM21 или
SPIM22 на пинах P1**. Именно так сделано в `sdcard_hwspi` (SPIM22).
